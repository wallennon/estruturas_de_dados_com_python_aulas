Recursividade

Uma função é recursiva quando, em algum ponto do seu corpo, ela chama a si mesma. Cada chamada empilha um novo contexto de execução, até que uma condição de parada diga: "pare e comece a voltar".

🔁 função chama função 🛑 condição de parada 📚 pilha de execução 🐍 Python
chamada(5)
chamada(4)
chamada(3)
chamada(2)
chamada(1) → condição de parada!

Cada chamada "empilha" um novo registro — e só desempilha quando a condição de parada é atingida.

Aquecimento

Isso é recursivo?

Recursividade aparece em vários lugares fora da programação. Clique nos cartões e veja se a ideia se encaixa.

Conceito-chave

Uma função que chama a si mesma

Recursividade é a técnica em que uma função, para resolver um problema, chama a si mesma para resolver uma versão menor do mesmo problema — até atingir um caso simples o bastante para ser resolvido diretamente, sem mais chamadas.

O que impede uma função recursiva de chamar a si mesma para sempre, travando o programa?

A condição de parada: é o caso-base que não gera nova chamada recursiva, interrompendo a cadeia de chamadas.
Sem condição de parada uma função recursiva chama a si mesma indefinidamente, até o programa travar por falta de memória — o famoso erro de "pilha cheia".
Por dentro da recursão

Cada chamada é um registro de ativação

Lembra da Pilha que estudamos? É exatamente essa estrutura — LIFO — que o Python usa por baixo dos panos para controlar as chamadas de função.

Registro de ativaçãoO "pacote" de memória criado a cada chamada: parâmetros, variáveis locais e para onde voltar quando a função terminar.
Chamar uma funçãoEmpilha (push) um novo registro de ativação no topo da pilha de execução.
Retornar de uma funçãoDesempilha (pop) o registro do topo e devolve o controle para quem chamou.
Recursão profunda demaisEmpilha tantos registros que a memória disponível para a pilha se esgota — erro de "stack overflow".
Ou seja: toda chamada de função — recursiva ou não — já usa uma pilha. A recursão só deixa isso mais visível, porque a mesma função aparece empilhada várias vezes.
Exemplo 1 · recursão de cauda

Imprimindo em ordem crescente

A chamada recursiva é a última ação da função — não existe nenhum código depois dela. Isso é chamado de recursão de cauda.

def crescente(n): if n == 0: return print(n) crescente(n - 1) # última instrução da função crescente(5)
Saída: 5 4 3 2 1 — cada chamada imprime o valor de n antes de chamar a si mesma com n - 1, então a ordem de impressão é a mesma ordem das chamadas.
Exemplo 2 · recursão não-cauda

Imprimindo em ordem decrescente

Agora o print acontece depois da chamada recursiva retornar — há código pendente esperando o resultado da chamada seguinte.

def decrescente(n): if n == 0: return decrescente(n - 1) # chamada ANTES do print print(n) # só executa quando a chamada de baixo retornar decrescente(5)
Saída: 1 2 3 4 5 — a ordem inverte! Cada chamada "pausa" no print pendente, esperando todas as chamadas de baixo terminarem primeiro, e os prints vão sendo executados ao desempilhar, do fundo da pilha para o topo.
Entendendo o desempilhar

Empilhar (ida) × desempilhar (volta)

⬇️ Fase de ida (empilhar)

decrescente(5) chama decrescente(4), que chama decrescente(3)... até decrescente(0), que bate na condição de parada. Nenhum print ocorreu ainda — todos ficaram pendentes.

⬆️ Fase de volta (desempilhar)

decrescente(0) retorna; decrescente(1) então executa seu print(1) pendente e retorna; decrescente(2) executa print(2); e assim por diante, até decrescente(5) imprimir 5 por último.

A regra geral: se o código pendente fica ANTES da chamada recursiva, ele executa na ordem das chamadas (ida). Se fica DEPOIS, ele executa na ordem inversa (volta).
Exemplo 3 · recursão de cauda

Somando um intervalo de números

def soma(m, n): if m == n: return n return m + soma(m + 1, n) print(soma(1, 5)) # 15
soma(1,5) empilha até soma(5,5) = 5; ao desempilhar, cada chamada soma seu m ao resultado de baixo: 4+5=9, 3+9=12, 2+12=14, 1+14=15
Classificação

Dois estilos de recursão

🏁 Recursão de Cauda

A chamada recursiva é a última ação da função — nada fica pendente esperando o retorno. Exemplos: crescente(n) e soma(m, n).

📈 Recursão Crescente

Existe código depois da chamada recursiva, que só executa quando ela retornar — o registro de ativação precisa "lembrar" o que falta fazer. Exemplo: decrescente(n).

Por que o nome "crescente"? Porque o trabalho pendente de cada chamada vai se acumulando enquanto a pilha cresce — só é de fato resolvido quando a pilha começa a desempilhar.
Pontos de atenção

O que levar desta aula

1. Condição de paradaToda função recursiva precisa de um caso-base — sem ele, a recursão nunca termina.
2. Custo de memóriaCada chamada recursiva cria um novo registro de ativação na pilha de execução, consumindo memória enquanto não retorna.
3. Cauda × crescenteRecursão de cauda não deixa trabalho pendente; recursão crescente acumula trabalho até o desempilhar.
4. Equivalência com laçosToda solução recursiva pode ser reescrita de forma iterativa (com for/while) — e vice-versa — ainda que a tradução nem sempre seja simples.
5. Risco de pilha cheiaRecursão profunda demais pode esgotar a pilha de execução disponível, interrompendo o programa com erro.
6. Mais conceitual que otimizaçãoRecursividade é, antes de tudo, uma forma elegante de estruturar o raciocínio sobre um problema — não é, por si só, uma técnica para tornar o código mais rápido.
Estudo de caso

A sequência de Fibonacci

Cada termo é a soma dos dois anteriores: 0, 1, 1, 2, 3, 5, 8, 13... A definição matemática é naturalmente recursiva, o que torna tentador escrevê-la assim em código.

def fibonacci_recursivo(n): if n <= 1: return n return fibonacci_recursivo(n - 1) + fibonacci_recursivo(n - 2)
Elegante, mas caro: para calcular fibonacci_recursivo(n), a função chama a si mesma duas vezes — e cada uma dessas chamadas chama a si mesma outras duas vezes. O número de chamadas explode.
Estudo de caso

A mesma sequência, sem recursão

A versão iterativa guarda apenas os dois últimos valores e avança em um laço — sem nenhuma chamada de função extra.

def fibonacci_iterativo(n): a, b = 0, 1 for _ in range(n): a, b = b, a + b return a

Quantas "chamadas extras" de função a versão iterativa de Fibonacci faz para calcular um termo?

Nenhuma: a versão iterativa só percorre um laço, atualizando duas variáveis — sem empilhar novos registros de ativação.
Impacto na prática

Fibonacci recursivo × iterativo

Valores aproximados, só para ilustrar a escala da diferença — o importante é a ordem de grandeza, não o número exato.

nRecursivo (ingênuo)Iterativo
20≈ 1 segundo≈ 0,001 ms
30≈ 2 minutos≈ 0,002 ms
50≈ 21 dias≈ 0,003 ms
100≈ 10⁹ anos≈ 0,0015 ms

10⁹ anos é mais tempo do que a idade do universo — e a versão iterativa continua em microssegundos.

Explicando o gráfico

O(2ⁿ) × O(n)

🐌 Recursivo — O(2ⁿ)

fibonacci_recursivo(n) chama fibonacci_recursivo(n-1) e fibonacci_recursivo(n-2), que por sua vez geram mais duas chamadas cada — o mesmo valor é recalculado centenas de vezes.

🚀 Iterativo — O(n)

fibonacci_iterativo(n) calcula cada termo uma única vez, guardando só o necessário para o próximo passo — o trabalho cresce de forma linear com n.

Memoização (teaser): é possível manter a versão recursiva e eliminar o recálculo, guardando em cache o resultado de cada fibonacci_recursivo(k) já calculado. Veremos essa técnica mais adiante no curso.

Fechamento

Recursividade, em uma frase

Uma função recursiva resolve um problema chamando a si mesma sobre uma versão menor dele, empilhando registros de ativação até atingir a condição de parada — e é, antes de tudo, uma ferramenta conceitual para organizar o raciocínio, não uma garantia de desempenho.
Para lembrar: 🛑 toda recursão precisa de condição de parada · 📚 cada chamada empilha um registro de ativação · 🏁 cauda = sem trabalho pendente · 📈 crescente = trabalho pendente até desempilhar · 🐌 cuidado com recálculos (Fibonacci ingênuo = O(2ⁿ)).
